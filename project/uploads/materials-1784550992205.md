- 开场加了一个"举手"钩子，结尾用"那杯咖啡"呼应开场，全场有了首尾闭合的画面感
- 全部讲稿按口语重写：短句多了，留了气口，删掉书面腔和排比腔，念出来像说话，不像读稿

- 每页结尾方式做了变化，不再页页收一句金句，避免听众疲劳
- 加了几处【讲法提示】，标在需要停顿或放慢的地方

## Slide 1｜标题页

**从法规知识到决策智能**
可信 AI 赋能全球化学品合规

屏幕上只放：中英文题目、姓名职位、REACH24H / 瑞欧科技、ChemCheck · KnowHub · Prowise Agent Runtime。

画面建议：不用机器人、发光大脑这类素材。用一张克制的全球法规关系网络，国家、监管机构、法规文件、企业产品之间以细线相连。

**讲稿**

大家好，我是朱海东。

今天的题目听起来有点大，从法规知识到决策智能。放心，我不讲模型，不讲架构，一页代码都没有。在座各位都是做法规的，我想讲的也是法规的事。

先问大家一个问题：今天早上，来会场之前，已经刷过一遍监管官网的，麻烦举个手。

【讲法提示：停两秒，看看反应，笑一下再继续。】

我猜不少。这个动作，就是我今天整场演讲的起点。一条新的监管动态，是怎么被我们发现的，怎么判断跟企业有没有关系，最后怎么变成一封邮件、一份报告、一个具体的合规动作。

这两年总有人问我，AI 到底能不能做法规。我的看法是：AI 进入这一行，不会从一个聊天框开始，而是从这些每天重复、又特别吃专业判断的小事开始。

今天我会反复提到一个词，Agent。大家不用管技术定义，把它理解成一位数字同事就行。会看网页、会读文件、会写东西的那种。

## Slide 2｜每天早晨，法规工作已经开始

**一杯咖啡背后的全球法规工作**

屏幕上放三个场景：查看各国监管官网 / 判断变化是否影响产品和客户 / 回复问题、准备报告或 Letter。背景可以是多个浏览器窗口、公告、邮件、产品清单，文字不要多。

**讲稿**

想象一个再普通不过的早晨。

咖啡刚泡上，你已经开了七八个网页。ECHA 的官网，美国 EPA，韩国环境部，可能还有某个东南亚国家刚改版的网站，搜索框换了位置，你得重新找。

【讲法提示：这段语速放慢，让大家在脑子里看见自己的桌面。"搜索框换了位置"通常会有会心的笑。】

刷到一条更新，工作才刚开始。先确认：官方发的吗？草案还是正式稿？什么时候生效，有没有过渡期？

然后是更难的问题：跟我有没有关系。管的是物质还是混合物？我们是制造商、进口商，还是下游用户？要不要更新 SDS，要不要改标签，供应链要不要提前动？

如果这时候客户的邮件正好进来，问的就是这条，你还得把要求讲明白。有时候一封邮件不够，得出正式的说明或者 Letter。

这样的早晨，瑞欧的同事过了十几年。每天如此。

## Slide 3｜找到一条消息，只是开始

**从监管动态到企业行动，中间还有很长一段路**

屏幕上放一条简洁流程：

发现信息 → 核实来源与版本 → 理解适用范围和要求 → 关联产品、市场和企业角色 → 形成建议、提醒、报告或 Letter

**讲稿**

一条监管消息本身，不是企业能直接用的答案。

同一项法规变化，落到两家企业身上，结论可能完全相反。一家在当地有进口主体，另一家只是给当地客户供货；一家的产品里确实含目标物质，另一家的产品名字很像，但用途和浓度都不一样。最后的义务，一个天上一个地下。

所以法规人员干的活，不是阅读加翻译。我们是把一条公开信息，放进企业的具体情况里，才能说清它到底意味着什么。

这也是为什么，合规问题靠搜索解决不了。搜索告诉你发生了什么。客户想要的是另外两句话：这跟我有没有关系？有关系的话，我接下来该做什么？

## Slide 4｜瑞查查是攒出来的

**不是一个建库项目，是很多个普通工作日**

屏幕上放一个循环：持续监测 → 专业解读 → 结构化整理 → 项目应用 → 专家反馈 → 持续更新。旁边一句朴素的话：今天看到的数据库，是很多个普通工作日攒起来的。

**讲稿**

很多人第一次看瑞查查，以为它是某一年立了个项，集中收了一批法规，就建成了。

不是的。它是攒出来的。

每天盯官网，核对文件，做项目，回答客户问题。新法规不断进来，旧法规不断修订，专家的理解也一点点补齐。这些东西一天一天记下来、理下来，才有了今天的瑞查查。

做数据库这件事，难的不是开始，是坚持。一条法规今天还是最新版，下个月可能就被修订了；去年的理解，今年一份实施指南出来，可能就要重写。得有人一直盯着。

投入确实大。但它有复利。攒了这么多年，别人要追，追的不是技术，是时间。

## Slide 5｜我们保存的，不只是法规文件

**数据要经过处理，AI 才用得上**

屏幕上分三层：

- 原始信息：法规、公告、指南、附件、官方问答
- 结构化知识：发布机关、适用范围、义务、豁免、日期、状态
- 专业经验：如何判断、何时追问、如何回复、哪些情况要专家介入

**讲稿**

现在把几千份 PDF 喂给大模型，技术上不难，一个周末就能搞定。但那不叫法规能力。

一份法规要真正能用，得先拆开：谁发布的，什么层级，什么时候生效，管谁，要求什么，有没有豁免，它改了哪部法，又被哪些指南解释过。拆出来的这些，才是知识。

还有一层，最难整理，就是经验。客户只给了一个产品名，能不能直接下结论？不能。得先问用途，问浓度，问供应链角色。哪些结论可以先给初步意见？哪些必须资深专家看过才能出门？

法规文件告诉 AI 规定是什么。瑞欧这些年做过的项目，告诉 AI 拿到一个具体问题时，该怎么干活。

## Slide 6｜一条法规，在系统里是一张网

**A regulation is not an isolated document**

画面建议：这页以图为主。中心一条法规，四周连接发布机关、上位法、修订法规、被引用法规、实施指南与 FAQ、适用物质和产品、企业角色、义务与豁免、历史项目、专家解读、客户问题与 Letter。屏幕上不放大段文字。

**讲稿**

在传统数据库里，一条法规就是一行记录。标题，国家，日期，附件。

但真用它的时候，谁会只看这一行？它上面有上位法，后面跟着修订案，旁边挂着技术标准。监管机构还会不断用指南、FAQ、执法案例去解释它。它还连着具体的物质、用途、吨位、供应链角色和义务。

所以在我们的体系里，法规不再是一份份孤立的文件，是一张网。

这一点对 AI 特别重要。只读一个条款，AI 的回答可能字面上对，实际只对了一半。它得看见整张网，才回答得了专业问题。

## Slide 7｜更难复制的，是瑞欧做事的方式

**从专家经验到 Agent 的行为准则**

屏幕左右对比：

- 通用模型天然会的：阅读总结、翻译、语言生成、一般性知识
- 瑞欧要教给 Agent 的：去哪找权威来源、怎么判断版本和效力、什么时候必须追问、怎么关联企业产品、哪些结论要升级审核、怎么形成客户能用的输出

**讲稿**

这两年大模型进步很快。阅读、翻译、总结，各家都不差，而且会越来越便宜。

但有一件事，模型自己学不会：瑞欧是怎么干活的。

它不知道我们查东西先信哪个来源。不知道客户只报一个产品名的时候，为什么不能直接给市场准入结论。也不知道一部法规虽然点名了某个物质，放进客户的具体用途里，可能压根不适用。

这些内容，任何法规原文里都找不到。它们在老同事的脑子里，在一个个做完的项目里，在跟监管机构的一次次沟通里。

我们现在做的，就是把这些一点点教给 Agent。什么必须先确认，哪些步骤不能跳，什么时候要停下来喊人，最后怎么把分析变成客户拿了就能用的东西。

## Slide 8｜为什么把 Agent 当同事

**工具每次从零开始，同事会在合作中成长**

屏幕上放六个词：岗位、工具、权限、记忆、反馈、成长。可以设计成一张"数字同事工牌"。

**讲稿**

为什么我们坚持把 Agent 当同事，不当工具？因为这两种想法，做出来的东西完全不一样。

当工具，你只关心一件事：这次它答对了没有。

当同事，要操心的就多了。想想我们平时怎么带新人：告诉他负责什么，给他资料和账号，讲清楚哪些系统不能碰、哪些决定不能自己拍板。他第一天肯定什么都不熟，你带他做项目，给反馈，他慢慢就上手了。

Agent 也一样。要有岗位，有权限，有工具，还得记得住事。做错了，不是把这次的答案改掉就完了，要想清楚下次怎么不再犯。

不过有一句话要说在前面：把它当同事，说的是协作方式，不是把责任交出去。最终的专业判断和合规责任，还是在人。

## Slide 9｜有用的 Agent，知道自己在为谁工作

**同一个问题，对不同企业不该是同一个答案**

屏幕上放四个区域：

- 企业：产品、市场、供应链角色、历史项目
- 用户：岗位、关注国家、专业背景、表达偏好
- 当前任务：已知事实、缺失信息、材料和进度
- 历史反馈：过去的判断、专家修改及原因

**讲稿**

光会干活不够。一个真正有用的 Agent，得知道自己在为谁干活。

举个例子，越南的新化学品法。同一条消息，一家企业在越南有工厂，一家通过当地进口商供货，还有一家暂时没有越南业务。这三家该做的事，完全不同。

同一个结论，写给法规经理和写给老板，写法也不该一样。有人要先看一句明确结论，再看依据；有人要逐条对法规原文；还有人直接说，给我一封能发客户的英文回复。

Agent 第一次跟你合作，可能只知道你这次问了什么。用得久了，它应该慢慢知道你管哪些产品，盯哪些市场，以前做过哪些判断，习惯什么表达。你不用每次都把背景从头讲一遍。

这是企业智库和网上问答工具最大的区别。

## Slide 10｜瑞查查、KnowHub 和 Prowise 怎样配合

**一套完整的工作环境**

屏幕上放四个模块，自上而下：

瑞查查 / ChemCheck（持续更新的全球法规事实）→ KnowHub 企业智库（企业知识、专题、产品背景和用户记忆）→ Prowise Agent Runtime（调用工具、处理文件、推进任务、形成交付物）→ 瑞欧法规专家（审核关键判断，提供反馈）

**讲稿**

讲到这里，把几个产品放在一起看，其实是一条线。

瑞查查，让 Agent 看得见外面的法规世界。持续更新的法规、监管动态、发布机关、实施状态，都在这儿。

KnowHub，让它认得出企业自己。你的法规库、专题、项目、内部材料，还有刚才说的那些记忆。

Prowise，是它上班的地方。会话、任务、文件、工具都在里面。它不是回一句话就完了，是把一件事从头推到尾，最后交出一份能用的东西。

专家始终在场。高风险的结论要专家把关，专家每一次修改，也在教它下次该怎么做。

这几块连起来，才是一位看得见法规、认得出企业、干得了活、还能慢慢长本事的法规 Agent。

## Slide 11｜一个实际工作场景

**当某国突然发布一项新的化学品管理要求**

屏幕做成六格故事板：发现官方信息 → 核实来源和状态 → 提取适用对象、义务和截止日期 → 关联企业产品和当地业务 → 形成影响分析和 Letter 草稿 → 专家审核并确认行动。

**讲稿**

来看一个具体场景。假设某天早上，某个国家突然发布一项新的化学品管理要求，限期完成申报。

过去的流程大家都熟。先得有人刷到这条消息，通读全文，弄清要求，再一家一家排查哪些客户受影响。消息要是晚看两天，留给客户的时间就少两天。

有了 Agent，节奏是这样的。

早上七点，它例行巡检官网，发现这条新公告。先核实来源和发布日期，确认是正式文件；然后提取适用对象、义务、截止日期和豁免情形；接着去翻企业智库：这家企业在当地有没有业务，哪些产品可能涉及，在供应链里是什么角色，以前有没有处理过类似的事。

九点，专家到办公室，打开的不是空白文档，是一份已经成型的初步分析：哪些产品要继续确认，还缺什么信息，建议在什么时间前做什么。客户要正式答复的话，Letter 草稿也按以前的项目模板备好了。

【讲法提示："早上七点""九点"这两个时间点要念出来，故事感全靠它们。】

专家做什么？审适用性判断，盯例外情况，把好最后对外的口径。

## Slide 12｜Agent 带来的不是无人化，是重新分工

**人负责判断，Agent 承担准备和执行**

屏幕两栏：

- Agent 更适合：持续监测、整理关联资料、跨文件比较、识别信息缺口、准备初稿和清单、追踪进度
- 专家更适合：复杂企业情境、灰色地带和例外、审核高风险结论、与客户和监管机构沟通、最终决定、教会 Agent 新经验

**讲稿**

所以 Agent 带来的不是无人化，是重新分工。

持续盯网站、整理关联材料、跨文件比对、找出信息缺口、备初稿、追进度，这些交给它。

复杂的适用性判断、灰色地带、跟客户和监管机构打交道、最后拍板，这些还是人的。

这个分工对企业还有另一层意义。过去很多关键能力，只装在少数几位资深同事的脑子里。项目一多，他们就是瓶颈；他们休个假，有些问题就得排队等。

Agent 取代不了这几位专家。它做的是另一件事：把专家的时间从重复劳动里捞出来，同时让专家的做事方法，被整个团队稳定地用起来。

## Slide 13｜它应该成长，但不能在后台随意改变自己

**成长需要专家审核，也需要留下记录**

屏幕上放一个循环：完成任务 → 专家修改 → 提炼候选经验 → 人工审核 → 更新记忆或工作规则 → 用历史案例验证。下方一句：被纠正一次，不等于可以自动变成长期规则。

**讲稿**

我们当然希望 Agent 越用越好。但有一条边界：它不能在后台悄悄改变自己。

举个例子。某次分析它漏了一项豁免条件，专家改了。系统会把这次修改记下来，再往前提炼一步：以后遇到类似情况，先确认哪些产品信息，哪些条件不满足就不能下结论。

但这条经验能不能长期用？只对这一家客户有效，还是全团队通用？必须专家审核。审核通过，它才进长期记忆和工作规则。

为什么这么谨慎？一次答错，只影响一个项目。一条错误的长期记忆，会影响后面所有项目。

所以每条记忆都要有来历。谁教的，什么时候，适用范围多大，审没审过。用户随时能看到 Agent 记了什么，不对的可以改，也可以删。

## Slide 14｜从法规知识到决策智能

**我们长期投入的，不只是一个更快的问答系统**

屏幕保留三段话，不放图表：

让 Agent 看见持续变化的全球法规。
让它记住企业、用户和过去的项目经验。
让法规知识最终变成判断、行动和可以审核的结果。

**讲稿**

回到今天的题目，从法规知识到决策智能。

这中间缺的，真不是一个更强的模型。模型会越来越强，也越来越便宜，谁都买得到。

买不到的，是一家企业攒了很多年的东西。每天维护的数据，一个个项目里攒下的经验，对客户的理解，还有一套被反复验证过的做事方法。

瑞欧现在做的，是让这些东西不只躺在数据库里，也不只留在几位专家的脑子里，而是能被 Agent 接过去，在人和 Agent 的长期协作里，继续往下攒。

AI 不会替代法规专家。它真正的价值，是让专家攒了半辈子的本事，被更多人、更稳定地用起来。

明天早上，咖啡还是那杯咖啡，官网还是那些官网。不同的是，等你坐下来的时候，可能已经有一位同事，替你把全世界看了一遍。

谢谢大家。
